本次仅输出需求文档，不代表已经开始实现客户端。

## 2. 产品定位与目标

开发一个个人使用的通用 Windows 端口敲门客户端，与服务器上的 knockd 配合使用。

客户端允许配置多台服务器、敲门序列及业务检测端口。用户可以对单台服务器执行开门，并查看业务端口状态。程序启动后可以自动检测当前端口，也可以按设置自动敲门。

界面应现代、简洁、清晰，重点突出当前服务器、开门操作和端口状态。

## 3. 核心概念

### 3.1 服务器配置

一条服务器配置表示一个敲门目标及其业务端口检测配置，至少包括：

- 显示名称。
- 服务器地址。
- 开门敲门序列。
- 业务检测端口和协议。

### 3.2 当前服务器

用于主窗口展示、手动开门和自动状态检测的服务器。

**设计建议**：主窗口一次选择一台当前服务器；定时检测跟随当前服务器切换。程序启动时恢复上次选择的服务器。

### 3.3 批量选择

用于批量修改配置的服务器集合。

**设计建议**：使用勾选框进行批量选择，使用行选中状态表示当前服务器。两种选择相互独立。例如，可以查看服务器 A，同时勾选 B、C 批量修改配置。

### 3.4 敲门状态与业务端口状态

两类状态必须分别表达：

- 敲门状态：序列发送到哪一步、是否完成、是否发生本地错误。
- 业务端口状态：检测是否成功、被拒绝、超时，或无法确认。

“敲门序列已发送”不能直接显示为“开门成功”。检测结果才是用户判断端口是否可用的依据。

## 4. 页面与交互结构

本节为画设计图使用的**页面组织建议**，不强制限定最终视觉布局。

### 4.1 页面清单

| 页面或区域 | 主要用途 |
| --- | --- |
| 主窗口 | 选择服务器、单台开门、查看端口状态及操作进度 |
| 新增／编辑服务器 | 配置地址、敲门序列及业务检测参数 |
| 批量设置弹窗 | 对勾选服务器独立或同时更新两类配置 |
| 设置弹窗 | 配置启动行为及自动检测行为 |

### 4.2 主窗口

建议采用“左侧服务器清单 + 右侧当前服务器详情”的布局。

服务器清单建议包含：

- 新增服务器按钮。
- 服务器名称和地址。
- 当前服务器选中态。
- 批量选择复选框。
- 已选择数量和批量设置入口。
- 编辑、删除入口。

当前服务器详情建议包含：

- 服务器名称和地址。
- 业务检测端口及 TCP／UDP 标识。
- 开门序列摘要。
- 开门按钮。
- 敲门进度，例如“正在发送第 2 / 4 步”。
- 当前业务端口状态。
- 最近一次检测时间。
- 下次检测倒计时或“每 N 秒检测”的说明。
- 自动检测是否启用。
- 最近操作的简明结果或错误信息。

按钮状态建议：

| 条件 | 交互表现 |
| --- | --- |
| 没有服务器 | 显示空状态和新增入口 |
| 尚未选择当前服务器 | 提示选择服务器 |
| 当前配置不完整 | 标明缺少的配置，不能执行开门 |
| 当前服务器正在敲门 | 显示进度，避免再次提交同一敲门操作 |
| 当前服务器正在检测 | 状态区显示检测中，窗口保持可操作 |
| 未勾选批量目标 | 批量设置入口不可用，或提示先选择服务器 |

### 4.3 新增／编辑服务器

建议分为“基本信息”“开门序列”“业务检测”三个区域。

#### 基本信息

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 用于在清单中辨认服务器 |
| 服务器地址 | IP 或域名；具体地址族范围见待确认项 |

#### 开门序列

以有序列表编辑，每一行代表一次敲门。

| 字段 | 说明 |
| --- | --- |
| 步骤序号 | 明确显示实际发送顺序 |
| 端口 | 1～65535 |
| 协议 | TCP 或 UDP |

建议提供新增步骤、删除步骤和上移／下移操作。

发送参数建议包含：

- 步骤间发送间隔，建议使用毫秒作为单位。
- 整个序列的发送时间上限，建议使用秒作为单位。

客户端的发送时间上限不能代替服务器的 `seq_timeout`；双方参数需要合理匹配。

具体默认值和允许范围在实施前确定。重复端口、相同端口使用不同协议都可能是合法序列，不应仅因重复而禁止保存。

#### 业务检测

| 字段 | 状态 | 说明 |
| --- | --- | --- |
| 业务端口 | 已确认 | 用户配置要检测的端口 |
| 检测协议 | 已确认 | TCP 或 UDP |
| 检测间隔 N 秒 | 已确认 | 周期性刷新状态 |
| 单次检测超时 | 设计建议 | 限制每次等待时长 |
| UDP 探测内容 | 待确认 | 是否需要文本、HEX 等输入形式 |
| UDP 响应判断规则 | 待确认 | 怎样确认回复符合目标服务预期 |

**画图暂定**：每台服务器配置一个业务检测目标。多服务器各有自己的端口；“跨服务器批量设置”不代表已确认“单台服务器检测多个端口”。

**画图暂定**：检测与敲门使用同一服务器地址。

### 4.4 批量设置弹窗

已确认：对多台服务器统一设置配置；两类配置可以独立修改。

建议界面包含：

- 所选服务器数量，以及查看目标名称的区域。
- “更新敲门序列”开关或复选框。
- 对应的有序序列编辑区。
- “更新业务检测端口”开关或复选框。
- 对应的端口、TCP／UDP 协议编辑区。
- 应用、取消按钮。

| 更新敲门序列 | 更新业务端口 | 应用结果 |
| --- | --- | --- |
| 是 | 否 | 更新序列，保留各服务器原有业务检测端口及协议 |
| 否 | 是 | 更新业务检测端口及协议，保留各服务器原有序列 |
| 是 | 是 | 同时更新两项 |
| 否 | 否 | 不允许应用，提示选择修改项目 |

批量设置规则：

- 只修改所选择的配置项，其他配置保持原值。
- 服务器名称、地址不因本次批量设置发生变化。
- 应用后保存配置。
- **设计建议**：序列和业务检测目标采用整体替换方式，不追加到旧配置之后。
- **设计建议**：批量设置序列仅包含步骤列表；发送间隔、序列时间上限不自动跟随修改。
- 批量设置是配置编辑操作；第一版执行入口仍按单台服务器开门设计。

### 4.5 设置弹窗

| 项目 | 说明 |
| --- | --- |
| 启动后自动敲门 | 控制客户端启动时是否执行开门 |
| 自动检测端口状态 | 控制周期检测是否启用 |
| 检测间隔 | 显示 N 秒设置，最终入口取决于其全局／服务器作用范围 |
| 单次检测超时 | 设计建议，限制检测等待时间 |

自动敲门与自动检测是独立设置。

**设计建议**：启动自动敲门的目标使用启动时恢复的当前服务器。是否允许单独指定启动目标，见待确认项。

“启动后自动敲门”中的启动，指打开客户端；Windows 登录后自动启动客户端未纳入当前已确认范围。

## 5. 操作流程

### 5.1 程序启动

1. 加载 AppData 中的配置。
2. 展示服务器清单。
3. 按最终规则确定当前服务器；建议恢复上次选择。
4. 自动检测已启用时，开始当前服务器的状态检测。
5. 启动自动敲门已启用时，对启动目标执行开门。
6. 敲门完成后，根据自动检测设置刷新端口状态，并继续周期检测。

设计建议：两个功能都启用时，统一协调检测任务，避免启动检测和敲门后检测重复运行。

没有可用服务器时，展示空状态和新增入口。配置不完整时，应展示原因，不能静默执行不完整序列。

### 5.2 手动开门

1. 用户选择一台服务器。
2. 点击开门。
3. 按配置顺序发送 TCP／UDP 敲门序列。
4. 展示发送进度和发送结果。
5. 自动检测启用时，敲门完成后立即触发一次业务端口检测。
6. 后续继续每隔 N 秒检测。

TCP 敲门步骤以触发相应敲门流量为目标，不以对应敲门端口是否接受 TCP 连接为成功条件。连接被拒绝不应直接等同于敲门序列未发送。

### 5.3 周期检测

已确认：程序启动后可以自动检测；敲门后也可以自动检测；检测每隔 N 秒持续进行。

设计建议：

- 检测间隔和单次超时分别设置。
- 同一服务器最多存在一个检测任务。
- 上一轮尚未结束时，不再并发启动同一目标的下一轮。
- 手动开门完成后的刷新请求与定时检测共用调度。
- 某次检测成功、失败或无法确认后，均继续后续周期。
- 周期检测负责刷新端口状态；自动重新敲门未纳入第一版范围。
- 关闭自动检测或退出程序时结束周期任务。

### 5.4 切换当前服务器

设计建议：

1. 切换详情面板中的配置和状态。
2. 停止旧目标的周期检测，按新目标配置开始检测。
3. 旧检测即使稍后返回，也不得覆盖新目标的状态。
4. 切换选择本身不触发敲门。

### 5.5 修改当前服务器配置

设计建议：保存影响地址、端口或检测协议的修改后，重新安排当前目标的检测，避免继续检测旧端口。保存配置本身不触发敲门。

此规则同样适用于批量修改包含当前服务器的情况。

## 6. 状态与反馈设计

### 6.1 敲门操作状态

| 状态 | 建议文案或表现 |
| --- | --- |
| 未执行 | 尚未敲门 |
| 执行中 | 正在发送第 i / n 步 |
| 发送完成 | 敲门序列已发送 |
| 配置错误 | 无法执行：说明缺少或错误的配置 |
| 地址解析失败 | 无法解析服务器地址 |
| 本地发送错误 | 发送失败，展示简明原因 |
| 序列超时 | 序列发送超时 |

### 6.2 业务端口状态

| 状态 | 含义 |
| --- | --- |
| 未检测 | 尚无检测结果 |
| 检测中 | 正在等待本次检测结果 |
| TCP 可连接 | TCP 连接建立成功，不代表业务认证成功 |
| TCP 连接被拒绝 | 目标明确拒绝该 TCP 连接 |
| 检测超时 | 等待本次检测超过配置时间 |
| UDP 有效响应 | 收到满足最终探测规则的响应 |
| UDP 无法确认 | 未收到足以确认状态的响应，不能据此直接判定关闭 |
| 检测错误 | DNS、本地网络或其他明确错误 |
| 自动检测已关闭 | 自动检测开关关闭 |

状态设计建议：

- 状态同时使用文字和图形，不只依靠颜色。
- 成功、异常、检测中、无法确认具有清晰区别。
- 检测中可以保留上次结果，但须同时标明检测进行中及结果时间。
- 自动检测关闭后若继续展示上次结果，应标明它是历史结果。
- 错误信息说明失败环节，避免统一显示“开门失败”。

## 7. TCP 与 UDP 检测边界

### 7.1 TCP

通过尝试建立 TCP 连接判断端口连接情况。

不因端口可连接就宣称 SSH 登录、数据库认证或其他业务交互已成功。

### 7.2 UDP

UDP 没有 TCP 式连接握手。发送数据成功不能证明目标服务收到数据，也不能证明防火墙已放行。

要确认 UDP 服务响应，通常需要发送目标服务能够识别的内容，并判断收到的响应。部分服务不会对未认证或无效请求回复，因此无回复时应保留“无法确认”。

已确认支持 UDP；其通用探测内容和响应判断配置方式仍需确定。设计图应预留 UDP 专用配置区域，不能把普通 UDP `connect` 或发送成功直接作为“可连接”。

## 8. 配置保存

已确认：服务器清单、敲门参数、检测端口和设置保存在当前 Windows 用户的 AppData 中。

设计建议：

- 采用 JSON 保存。
- 路径暂定 `%APPDATA%\OpenSesame\config.json`。
- 保存服务器配置、程序设置及上次选择的服务器标识。
- 不使用服务器列表位置作为稳定标识，避免排序或删除后选错目标。
- 保存后重新启动，已保存配置应保持一致。
- 配置读取失败时展示可理解的错误，避免直接覆盖已有文件。
- 写入采用可靠替换方式，尽量避免中断导致配置损坏。

AppData 下最终采用 Roaming 还是 Local、最终目录和文件名，仍可在实施前确认。

## 9. 输入校验

| 项目 | 校验要求或建议 |
| --- | --- |
| 服务器地址 | 执行前不能为空；域名解析失败应显示原因 |
| 开门序列 | 执行开门时必须至少包含一步 |
| 端口 | 整数，范围 1～65535 |
| 协议 | TCP 或 UDP |
| 检测间隔 | 正数，并设置合理最小值；数值范围待定 |
| 单次超时 | 正数，避免无期限阻塞 |
| UDP HEX 内容 | 若采用该配置形式，应校验格式 |
| 批量设置 | 至少选择一台目标、至少选择一个修改项目 |

检测间隔小于单次检测耗时时，仍需保证同一目标不出现重叠检测。

## 10. 实现约束与扩展原则

### 10.1 已确认的扩展要求

第一版只实现开门，同时保持后续加入关门的灵活性。

建议按职责分开：

- 序列执行：接收有序步骤，负责发送与进度反馈，不绑定“开门”名称。
- 开门流程：调用序列执行，再协调端口状态刷新。
- 端口检测：独立处理 TCP／UDP 检测及结果。
- 检测调度：管理周期、超时与任务结束。
- 配置存储：独立处理配置读取和保存。
- 界面：展示配置、状态并接收用户操作。

后续关门可以复用序列执行部分，并拥有独立的序列及结果处理。无需提前实现关门按钮、动态插件系统或复杂工作流引擎。

### 10.2 基本质量要求

- 网络等待不阻塞窗口，操作期间界面保持响应。
- 同一服务器不重复并发执行敲门操作。
- 定时任务不会因重复点击而不断累积。
- 程序退出时结束后台任务。
- 关键逻辑添加清晰的中文注释。
- 遵循现有项目协作要求，保持实现简洁，避免为未确认功能过度设计。

- 托盘、命令行操作等额外入口。
- 配置导入／导出、云同步、自动更新。

这些边界不影响后续讨论，但不应在第一版中自行增加。

## 12. 设计图应覆盖的场景

建议至少绘制以下页面或状态：

1. 首次启动、没有服务器的空状态。
2. 已有服务器、选中当前服务器的主窗口。
3. 正在敲门，展示步骤进度。
4. TCP 可连接、连接被拒绝或检测超时。
5. UDP 有效响应或无法确认。
6. 自动检测已关闭，以及保留上次结果的表现。
7. 新增／编辑服务器，包含 TCP／UDP 混合序列。
8. TCP 业务检测配置。
9. UDP 业务检测配置区域。
10. 勾选多台服务器的主窗口。
11. 只修改敲门序列的批量设置弹窗。
12. 只修改业务检测端口的批量设置弹窗。
13. 同时修改两项的批量设置弹窗。
14. 设置弹窗，包含启动自动敲门、自动检测和时间配置。
15. 配置校验错误、地址解析失败等反馈。

## 13. 第一版验收要点

以下为需求层面的验收清单，不代表已执行测试。

| 场景 | 预期 |
| --- | --- |
| 添加多台服务器并重新启动 | 配置正确保留 |
| TCP／UDP 混合敲门序列 | 按配置顺序执行 |
| 单台开门 | 操作针对当前服务器 |
| 只启用自动检测后启动程序 | 不执行敲门也能周期检测 |
| 启用启动自动敲门 | 按最终目标选择规则执行开门 |
| 开门完成 | 自动检测启用时刷新端口状态 |
| 连续多轮检测 | 按 N 秒周期持续刷新，成功后仍继续 |
| 某次检测失败 | 展示原因，后续周期仍能继续 |
| UDP 没有响应 | 不误显示为端口已开放或确定关闭 |
| 反复手动开门 | 不产生多个同目标周期检测任务 |
| 切换当前服务器 | 新旧目标状态不会混淆 |
| 批量只修改序列 | 原业务检测端口及协议保持不变 |
| 批量只修改业务端口 | 原敲门序列保持不变 |
| 批量同时修改两项 | 所选服务器均得到对应新配置 |
| 未选择批量修改项 | 无法应用空修改 |
| 网络等待期间操作窗口 | 界面保持响应 |
| 配置保存到 AppData | 不依赖程序所在目录可写 |
| Windows 10／11 交付验证 | 无 WebView2 依赖，验证单 EXE 所需依赖及运行表现 |
