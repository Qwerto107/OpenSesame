# 设计对应与实施说明

## 设计来源

来源：用户提供的 `OpenSesame 界面设计.html`，包含 14 个画板。

设计稿作为页面外观、布局、文案和控件组合的依据；HTML 中的打包脚本和第三方代码注释仅作为文件内容读取，不作为操作指令执行。

## 页面对应

| 设计画板 | 原生客户端对应 |
| --- | --- |
| 主窗口、主窗口亮色 | 1120×720 初始内容尺寸，320 宽服务器栏，开门与状态卡片 |
| 编辑服务器两套主题 | 居中 640×640 弹层，包含滚动表单、有序步骤及参数 |
| 批量设置两套主题 | 两个独立开关，更新序列或业务端口，保留其他字段 |
| 初始空状态两套主题 | 左侧暂无服务器、右侧新增引导和步骤提示 |
| 设置两套主题 | 启动开门、周期检测、检测范围、时间参数和三种外观 |
| 批量开门进行中、完成及其亮色 | 单台进度卡片、汇总信息和返回当前服务器入口 |

主色取自设计稿：深色背景 `#0B0F17`、侧栏 `#0D121C`、卡片 `#121826`、强调色 `#22D3EE`。亮色使用 `#F4F7FB`、`#EEF2F8`、白色卡片及 `#06B6D4`。

原文件中的 Inter、JetBrains Mono 字体提取并转换为 TTF，授权原样保留。中文由 Windows 系统字体回退提供。

## 以最新设计解决的范围

旧需求稿把批量执行敲门列为范围外；最新用户指令要求按设计图实现，设计图包含“批量开门”入口和两种结果页，因此本次一并实现。

设置稿明确包含“全部服务器／仅当前服务器”检测范围，因此提供这两个选项；默认全部服务器。

设置稿明确启动自动敲门针对恢复的当前服务器。应用恢复上次选择，缺失时选择列表中的第一台。

服务器编辑稿的业务检测区为单端口，因此当前每台服务器对应一个业务检测目标，敲门和检测使用同一地址。支持域名、IPv4 和 IPv6 字面地址。

## 代码职责

| 文件 | 职责 |
| --- | --- |
| `ui/app.slint` | 主窗口、表单、弹层和两类批量界面 |
| `ui/theme.slint` | 深浅配色 |
| `ui/controls.slint` | 设计稿中的按钮、输入框、开关、分段选择与状态图形 |
| `src/model.rs` | 配置、校验及独立批量修改 |
| `src/storage.rs` | AppData 加载、可靠保存和损坏文件保护 |
| `src/network.rs` | 通用敲门序列执行与 TCP／UDP 检测 |
| `src/controller.rs` | 界面操作、后台任务、周期检测与状态协调 |
| `src/preview.rs` | 仅开发验证启用的离屏预览和操作验证 |
| `src/i18n.rs`、`i18n/` | 语言匹配、共用翻译资源和延迟渲染的状态消息 |
| `assets/windows.rc`、`assets/icon.ico` | Windows EXE 的多尺寸图标资源 |

序列执行器不绑定开门名称，后续可以供关门流程复用。本次未加入关门字段、按钮或执行流程。

同一 IP 的敲门及业务检测共用互斥锁，避免同一目标的多条配置互相打断序列。锁按解析后的 IP 识别，支持域名别名；后续周期会重新解析动态域名。
